# r107 / RTX 5090 reproduction profile

This profile records the environment and request grid used to evaluate the
`r107` optimization revision. It is descriptive: it does not start or manage
the inference server.

## Environment

- Release tag: `v0.27.1-qwen38-r107-cu130-sm120`
- Model: `RadixArk/Qwen3.8-27B-NVFP4`
- Served model name: `qwen/qwen38-nvfp4`
- GPU: one NVIDIA GeForce RTX 5090 (`sm_120`)
- Operating system: Ubuntu 24.04, `x86_64`
- Python: CPython 3.12
- CUDA Toolkit/runtime: 13.0
- PyTorch: `2.13.0+cu130`
- vLLM: `0.27.1+qwen38.r107.cu130.sm120`
- Benchmark client: `tool-eval-bench 2.5.1.dev46+gd4381ce5c`
  ([commit `d4381ce5c`](https://github.com/SeraphimSerapis/tool-eval-bench/commit/d4381ce5c))

## Server contract

The evaluated server used the following vLLM arguments. The model path can be
a Hugging Face ID or an equivalent local snapshot.

```bash
vllm serve RadixArk/Qwen3.8-27B-NVFP4 \
  --served-model-name qwen/qwen38-nvfp4 \
  --host 0.0.0.0 \
  --port 8000 \
  --max-model-len 262144 \
  --kv-cache-dtype turboquant_4bit_nc \
  --kv-cache-memory-bytes 5905580032 \
  --max-num-seqs 4 \
  --max-num-batched-tokens 12480 \
  --long-prefill-token-threshold 3120 \
  --adaptive-long-prefill-threshold \
  --gpu-memory-utilization 0.91 \
  --attention-config.flash_attn_version=2 \
  --enable-auto-tool-choice \
  --tool-call-parser qwen3_xml \
  --reasoning-parser qwen3 \
  --speculative-config '{"method":"mtp","num_speculative_tokens":3}' \
  --compilation-config '{"cudagraph_mode":"FULL_AND_PIECEWISE","pass_config":{"fuse_act_quant":true,"act_quant_fusion_min_token_num":33}}'
```

Automatic prefix caching was not explicitly enabled in this profile. Keep the
cache policy and server lifecycle identical when comparing two revisions.

## Throughput protocol

The throughput run uses `--perf-legacy-only` and the following fixed grid:

| Setting | Value |
| --- | --- |
| Prompt tokens | 2,048 |
| Generated tokens | 128 per request |
| Context depths | 0, 4,096, 8,192, 16,384, 32,768, 65,536 |
| Concurrency | 1, 2, 4 |
| Timeout | 300 seconds per request |
| Cells | 18 |

The client-observed aggregate `tg t/s` is the comparison metric for each cell.
It includes prefill time and must not be described as pure decode throughput.
The suite score used during optimization was the geometric mean across all 18
successful cells.

Reproduce the run with:

```bash
LABEL=r107-sm120-throughput ./benchmarks/benchmark_throughput.sh
```

## Tool-call protocol

The quality gate uses the deterministic short suite:

| Setting | Value |
| --- | --- |
| Suite | Core 15 scenarios (`--short`) |
| Seed | 42 |
| Trials | 1 per scenario |
| Parallel scenarios | 1 |
| Timeout | 300 seconds per request |
| Sampling temperature | 0 |

Reproduce the run with:

```bash
LABEL=r107-sm120-tool-calls ./benchmarks/benchmark_tool_calls.sh
```

Retain the complete Markdown reports, raw traces, completion rate, and benchmark
client version when publishing or comparing results.
